### Companion Guide: Mesh-Mode Freeze and Stability Fixes (CR 1021–1025)

What we’re fixing
- Window freeze when triggering mesh shader mode (likely due to host-side blocking waits on timeline semaphores).
- Validation spam hides signals and may mask crashes.
- Persistent TAA pipeline layout VUID 07988 and coarse grid layout spam (01197/09600) already covered by prior CRs, but referenced for completeness.

Root causes observed
- Host wait in render path: MeshParticleRenderer calls vkWaitSemaphores on the CPU (blocking), which can stall the UI thread.
- GPU submission model mixes legacy submit and SubmitInfo2; TLAS/BLAS builds signal readiness ambiguously.
- Descriptor push logs show only external TLAS; shell TLAS absent → self-shadows not visible.
- TAA pipeline creation occasionally hits VUID 07988 (shader expects binding not in layout).
- Console spam from repeated descriptors/status/validation floods logs.

Apply in this order
1) 1021_timeline_gpu_signal — Move timeline signal/wait to GPU submits; remove host blocking wait.
2) 1022_mesh_freeze_guard — Non-blocking guard for shell TLAS; keep rendering even if TLAS pending.
3) 1023_sync2_unify_single_time — Use SubmitInfo2 consistently for single-time cmds + proper stages.
4) 1024_taa_layout_07988 — Align TAA shader bindings with layout; rebuild pipeline.
5) 1025_log_throttle — Reduce log spam to keep critical info readable.

—

CR 1021 — GPU timeline signal/wait
- Actions: Submit BLAS with signal timeline=N; submit TLAS wait=N signal=N+1; frame graphics submit waits on N+1; delete vkWaitSemaphores on host.
- Acceptance: No freeze on mesh mode; logs show timeline values in GPU submits; no host waits remain.
- MCP: get_vulkan_entity('VkSemaphoreSubmitInfo'), get_vulkan_entity('VkSubmitInfo2').

CR 1022 — Mesh render guard
- Actions: If shell TLAS not ready, skip binding_4; set push constant flag to disable self-shadow path; keep external occluders if available. Throttle status, e.g., every ~120 frames.
- Acceptance: Rendering continues; descriptor push shows 2 or 3 bindings depending on readiness.
- MCP: search_vulkan_spec('Push descriptors optional bindings').

CR 1023 — SubmitInfo2/Sync2 unification
- Actions: Replace legacy submit calls in single-time helpers with SubmitInfo2; specify src/dst stages for AS build, blit, compute, graphics; avoid device-wide waits.
- Acceptance: Consistent submits; no barriers/copies inside dynamic rendering.
- MCP: get_vulkan_entity('VkSubmitInfo2'); search_vulkan_spec('Synchronization2 stages for AS build and blit').

CR 1024 — TAA layout 07988
- Actions: Ensure taa.frag only declares bindings present in m_taaDescriptorSetLayout; or compile variant with unused paths removed; rebuild pipeline; log bindings.
- Acceptance: No VUID 07988 at TAA pipeline creation; TAA works.
- MCP: search_vulkan_spec('VUID-VkGraphicsPipelineCreateInfo-layout-07988').

CR 1025 — Log throttle
- Actions: Throttle “Pushed descriptors…”, bounds overlay, periodic status; add simple duplicate-message suppression for validation output; introduce log levels.
- Acceptance: Logs remain readable; critical events visible.

Verification checklist
- Enter mesh mode: UI remains responsive; FPS prints continue.
- Logs: “graphics submit waits timeline=N+1” and “pushed descriptors: particle_buffer external_TLAS [shell_TLAS]”.
- Shader overlay (from prior CR 1018) shows hits when shells active.
- No TAA layout VUID 07988; reduced validation spam.

If still freezing
- Verify no remaining vkWaitSemaphores on the CPU path.
- Confirm graphics submit actually waits on timeline semaphore N+1 via SubmitInfo2.
- Temporarily disable shell extraction to isolate (toggle). If stable, re-enable with larger interval and confirm GPU signaling.
